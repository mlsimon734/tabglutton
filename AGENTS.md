# Repository Guidelines

The rules in this file are load-bearing; the measured histories behind them live in `docs/ENGINEERING.md` (the `§` references below) and `docs/BRIDGE.md`. **Before touching bridge, clip, permission, icon, build, or release code, read the matching section there** — several of these rules exist precisely because a plausible simplification once undid the fix they pin.

## Project structure

Bun-powered TypeScript WebExtension ("Tabglutton") for Zen Browser, Firefox, and Chrome, plus `gullet/`, the agent-bridge sidecar (its own section below).

- `src/` — `background.ts` wires browser events and owns `clipTab`/`ensureTabReady`; `dedup.ts` plans duplicate closures (`pickKeeper` lives here); `normalize.ts` canonicalizes URLs; `storage.ts` settings; `grouping.ts` and `site-rules.ts` rule-based grouping and user-editable site rules; `clip-current.ts` the Defuddle extractor injected by Devour; `clip-format.ts` Obsidian markdown + the `obsidian://new` URL; `clip-file.ts` the file destination; `clip-guard.ts` the thin-extraction floor; `clip-memory.ts` what has been clipped; `zotero.ts` the Connector route; `permissions.ts` grant prompts and their user-facing sentences; `serialize.ts` the queues; `diagnostics.ts` the "Copy diagnostics" vocabulary; `target.ts` exposes `IS_CHROME`/`IS_FIREFOX`. Bridge: `bridge-protocol.ts` (wire contract, shared with the sidecar), `bridge-client.ts` (loopback WebSocket client + alarm-driven reconnect), `bridge-methods.ts` (tool implementations), `undo-log.ts` (close/undo trail).
- `popup/` (`lib.ts` builds the list model both the popup and the Devour cockpit render — duplicate sets lead it instead of appearing in their host groups, so every tab renders once; §Popup list model), `options/`, `onboarding/`, `redirect/` (the cross-browser `obsidian://` launch shim), `icons/`.
- `manifest.json` is the Firefox shape, patched in memory for Chrome by `build.ts` (`--target=firefox|chrome|all` → `dist-firefox/`, `dist-chrome/`). `dist-*/`, `.dev-profile*`, and `web-ext-artifacts/` are generated output. `scratch-chrome/` holds gitignored, local-only CDP harnesses — copy it across worktrees rather than reinventing it.
- Docs: `docs/BRIDGE.md` (bridge design, wire protocol, tool surface, open questions), `docs/ENGINEERING.md` (measured histories), `docs/STORE.md` (AMO/CWS listing; screenshots §5, credentials §7), `gullet/README.md` (sidecar setup, config, troubleshooting), `CHANGELOG.md`.

## Cross-browser build

- Sources stay shared: `src/target.ts` is checked in as `TARGET = "firefox"` and `build.ts` rewrites the compiled `dist-chrome/src/target.js`; sources are never mutated. Chrome uses `webextension-polyfill`, inlined into the `Bun.build` service worker and injected as `vendor/browser-polyfill.js` into the HTML pages, before the module script tag.
- Chrome manifest patches, all in `build.ts`: drop `browser_specific_settings`; `background.scripts` → `service_worker`; SVG icons → PNG (`icons/icon-chomp-{16,32,48,128}.png`); `minimum_chrome_version: "120"` (116-119 clamp alarms to one minute, which breaks the 30s reconnect alarm; §Chrome build); `host_permissions` → `optional_host_permissions`; `options_ui.open_in_tab: true`.
- **Icons are the extension's own mark, drawn twice** (`icons/icon-chomp.svg` duplicates `logo-mark.svg`; `docs/media/promo-tile.html` is a third copy; `tests/logo-mark.test.ts` pins them). Regenerate with `bun scripts/rasterize-icons.ts`, never all four sizes from one source — 16/32 come from `icon-chomp-small.svg`. AMO never reads the manifest `icons` key: the listing icon and screenshots are Developer Hub uploads. §Icons.
- Chrome has no `tab.hidden` or `getBrowserInfo`: `scope` defaults to `"current-window"`, `probeHeuristic` and the `hidden: false` query branch short-circuit, and options hides the scope radio group.
- Chrome rejects the Firefox-only `tabs.onUpdated` filter (aborting service-worker registration); register through `onTabUpdated`, which drops it on Chrome. §Chrome build.
- Chrome validates injected scripts with `base::IsStringUTF8`; `build.ts` escapes noncharacters and unpaired surrogates after bundling (`escapeChromeUnsafeCodePoints`). §Chrome build.
- `web-ext lint` is Firefox-only; `lint:ext` lints `dist-firefox/`. The Chrome zip is validated by the Web Store upload.
- `manifest.json` must keep its explicit `content_security_policy.extension_pages` — Firefox's default MV3 CSP adds `upgrade-insecure-requests`, which rewrites `ws://` to `wss://` and makes bridge dials fail invisibly with close code 1015. §Extension CSP.

## Clipping and destinations

- **The `obsidian://` handoff launches through `redirect/obsidian-redirect.html` on both engines**, never a direct `tabs.create`; onboarding bootstraps the protocol grant from that origin, and the step is conditional — onboarding's sequence is a list of step keys, not a count, so a walkthrough that files to disk never needs it. Keep the Firefox dev scripts free of protocol-handler pref overrides. The `expectedUrl` passed to `ensureTabReady` is load-bearing. Gullet's check remains the only confirmation a bridge clip reached disk ([#18](https://github.com/mlsimon734/tabglutton/issues/18)). §Obsidian launch.
- **The clip destination is chosen, never inferred, and the bridge obeys the same choice the popup does.** `clipDestination` is Obsidian (default) or a markdown file; nothing switches on the user's behalf. `tab_clip` runs the same `clipDestinationFor` and `zoteroDestination` routing as Devour (injected as `routesToZotero`, Connector details in `src/zotero.ts` alone; [#50](https://github.com/mlsimon734/tabglutton/issues/50)) but refuses a discarded tab instead of waking it. A `vault` override outranks both. A Connector that cannot answer fails with `zotero-failed` and **never** falls through to Obsidian. `docs/BRIDGE.md` §Tool surface (v2).
- **File mode**: Gecko refuses `data:` URLs synchronously and Chrome MV3 has no `createObjectURL`, so `downloadUrlFor` branches on `IS_CHROME`; folder segments go through `sanitizePathSegment`; `saveClipFile` waits for `state: "complete"`, and an erased download record answers `confirmed: false` (fail-open, tab kept). §File destination, §Clip verification.
- **Thin extractions are measured in one place** (`src/clip-guard.ts`, `MIN_CLIP_CONTENT_CHARS`, applied at `clipTab`) **and refused by whoever would write**: Devour and `tab_clip` refuse; `tab_read` returns the text plus a `thin` note. `ok` goes false and the refused text moves onto the verdict, never back onto `payload`; the verdict is read before site access is questioned; length is the detector and signatures only sharpen the message ([#49](https://github.com/mlsimon734/tabglutton/issues/49)). §Clip guard.
- **The `downloads` grant is optional, revocable, and answered once per run before phase 1 wakes anything** (`blocked: "downloads-revoked"` only when nothing could route elsewhere); `downloadsGrant()` answers `unknown` on a throw and callers carry on. The options page reverting the destination to Obsidian on load is what makes the remedy real. User-facing sentences live in `permissions.ts`. §Host permissions.
- **Clip memory records intent** (`src/clip-memory.ts`, keyed by `normalizeUrl`, through a `serialize.ts` queue): `launched` vs `verified` is derived from a `verifiedAt` timestamp, produced only by the browser watching a download complete or Gullet finding the note — so **no surface may say "in your vault"**. `clip_confirm` is in `BRIDGE_SIDECAR_METHODS`, deliberately not `BRIDGE_METHODS`. §Clip memory.
- **`clip-current.ts` parses a detached snapshot through `parseAsync`, and that is what makes YouTube transcripts arrive.** The snapshot's missing `defaultView` sends every Defuddle extractor down its off-browser route (YouTube caption tracks, Reddit comments pages via old.reddit / the Atom feed, logged-out x.com via oEmbed); a fetch that throws falls back to the sync parse. Do not restore `useAsync: false`; the clip's 10 s ceiling is the only cap on those fetches. §Async extraction.

## Permissions and injection

- **Host permissions are required on Firefox and optional on Chrome, from one manifest.** `requestOrigins` must be the **first** `await` in a click handler with no `contains()` pre-check; the `hasOrigins` fallback on `false`/throw carries Firefox entirely — **do not simplify it away**. A missing grant is not a probe miss (it never advances `PROBE_MISSES_BEFORE_DIALLING_BLIND`) and is cached per page. The bridge cannot ask, so `readTab` checks the grant only after extraction has failed. §Host permissions.
- **"Missing host permission for the tab" is Gecko's catch-all for an injection with no results** (mid-navigation frames, or `extensions.webextensions.restrictedDomains` hosts no grant ever lifts). `readTab` retries once after 250ms, then reports the engine's message plus `NO_INJECTION_TARGET_HINT` — never a "retry" remedy. The grant check stays ahead of the retry; don't gate the retry on `tabs_load`. §Restricted injection.
- `options_ui.open_in_tab` is static and the engines want opposite defaults: the source says `false`, `build.ts` patches Chrome to `true`, `options.ts` hides `#optionsLayout` on Chrome, `openOptionsUi` short-circuits on `IS_CHROME`. §Options page.
- **The duplicate notice is the extension's own page framed into someone else's, and a web-accessible frame is not a trusted one.** `src/dup-notice-page.ts` (injected, no `browser` global, one IIFE for both targets) embeds `notice/dup-notice.html`; its two actions go through `dup-notice-act`, never the popup's `close-duplicates` / `reopen-tabs`, and carry a per-notice nonce (`crypto.randomUUID`, kept in `storage.session`) the background checks, crossed by `postMessage` from the host content script and never in the frame URL. The options switch asks `requestOrigins(CLIP_ORIGINS)` first-await, refuses on `false`, and reverts on load when the grant is gone; the announced memory is `storage.session` and a disabled setting leaves it untouched; `reopen-tabs` marks the pile announced before its badge pass; a badge pass with any tab mid-navigation is a floor and never disarms. Decision logic is pure in `src/dup-notice.ts`; the injection is live-only. §Duplicate notice.

## Tabs and the bridge (extension side)

- Chrome mints a **new tab id on discard** (Firefox keeps it), so `bridge-methods.ts` appends `STALE_ID_HINT` to every "no such tab id" error. Measurement in `docs/LAUNCH.md` ("Chrome assigns a new tab id"); the unreadable-discarded-tab side is `docs/BRIDGE.md` §The discarded-tab problem.
- **Waking is `tabs.reload()`, never `tabs.update({ discarded: false })`.** `ensureTabReady` owns it for Devour and `tabs_load`, attaches its `onUpdated` listener before reading the tab, and reads no status after the reload. §Waking tabs.
- **Grouping** (`tabs.group()`) churns no tab ids and wakes no discarded tab, needs the `tabGroups` permission, and **silently unpins pinned tabs** — a rule pass excludes them or says so ([#33](https://github.com/mlsimon734/tabglutton/issues/33)). §Tab grouping.
- Neither engine reports a real URL until navigation commits (Chrome `url: ""` + `pendingUrl`, Gecko `about:blank`); read URLs through `tabUrl`. §Uncommitted URLs.
- Chrome's `tabs.remove` rejects the whole batch at the first stale id after closing everything ahead of it: `parseTabsCloseParams` dedupes, and `removeTabs` retries each id alone, then asks which ids still exist — absence is the signal. §Batch removal.
- **Never open a WebSocket at a port that has not answered, and give the dial its own long deadline**: `BRIDGE_DIAL_TIMEOUT_MS` stays 120s (twice Gecko's FailDelay ceiling); the fast-retry burst arms only after losing an established connection; `BridgeClient` probes over HTTP first and never hands a markerless response a token proof; idle-loop misses never count toward dialling blind; the miss counter is instance-only. §FailDelay.
- **Bridge requests are served concurrently, so anything browser-global gets a queue** (`withUndoLog`, `withClipMemory`, the Obsidian handoff queue — all `src/serialize.ts`); Zotero saves go through a global ceiling of `ZOTERO_SAVE_CONCURRENCY` instead ([#51](https://github.com/mlsimon734/tabglutton/issues/51)). §Concurrency.
- **Nothing is closed that the undo log could not put back**: entries are paired before removal, unrecordable tabs stay open (`skipped`), the batch is written before the removal and reconciled after, and `closed` always equals `entries.length`. §Undo invariants.
- The first-`tabs_list`-times-out report ([#27](https://github.com/mlsimon734/tabglutton/issues/27)) is diagnosed, not fixed; both hypotheses are measured out. **Do not wrap `tabs_list` in a retry.** `docs/BRIDGE.md` §Open questions.
- **Digests are matched by tab id and URL together, or refused as ambiguous; the note is Gullet's, written straight to disk once per `digest_id`; agent text renders through `textContent` only; Undo is read from the undo log.** `src/digest.ts` is the pure model, `src/digest-actions.ts` the panel's messages, `gullet/src/digest-mirror.ts` the note. §Digest.
- **Never log a `Settings` object** — it carries `bridgeToken`. Use `loggableSettings`; "Copy diagnostics" is assembled field by field in `collectDiagnostics` from the `DiagnosticsFacts` vocabulary; the bridge error log records a closed-set kind, never a caught error's message. There is no redaction pass and must not be one. §Secrets in logs.

## Gullet (agent bridge sidecar)

`gullet/` is a sibling package (own `tsconfig.json`: ES2022, `bun-types`, no DOM; zero dependencies), excluded from the extension `tsconfig.json` so it never reaches `dist-*`; `bun run build:gullet` bundles the `tabglutton-gullet` npm package. It shares `src/bridge-protocol.ts` with the extension; its listing renderer is `gullet/src/tabs-view.ts`. Setup and troubleshooting: `gullet/README.md`.

- Config lives at `${XDG_CONFIG_HOME:-$HOME/.config}/tabglutton/config.json` with the token in a separate `0600` file; an inline `"token"` key is rejected. Token precedence is `--token` → env → `tokenCommand` → `tokenFile` → default file → `./.env`, and **`./.env` stays last** (it answers only on ENOENT of the global file). `tokenCommand` is bounded and lazy, faults through `Supervisor.fault()`, and is retried with backoff — do not move it ahead of that path. §Gullet token precedence.
- **A clip is confirmed on disk before anything is closed, and `confirmedBy` says who could**: `browser` for file and Zotero clips; Obsidian clips leave the extension as `nobody`, and `clip-verify.ts` upgrades them to `gullet` when it finds the note. `nobody` is fail-open, with different consequences per destination: an unverifiable Obsidian clip still closes, an unverifiable file clip keeps its tab. `clipAndVerify` owns the close for both (clip with `close: false`, verify, then `tabs_close`, which may fail). Existence is not proof — freshness, `isClipNoteName`'s numbered variants, `source` attribution, `contentHash`; an empty note never lands; only `ENOENT` means "not written". §Clip verification.
- Diagnostics go to **stderr only** — stdout is the MCP transport. Socket tests bind port 0.
- **The stdio pump dispatches concurrently and serializes only the writes**, chaining on the write callback; `McpTransport` is injectable so this is testable. §stdio pump.
- **Hub election** runs across the ordered, append-only `BRIDGE_PORT_CANDIDATES`; losers attach as peers and proxy through the hub (peers are never bridge-method targets; probe before attaching). `start()` bounds the wait (`ELECTION_START_TIMEOUT_MS`), not the election; `ToolContext.startupError` is a function so a freed port heals in place. §Hub election.
- **The hub is a detached process** ([#29](https://github.com/mlsimon734/tabglutton/issues/29); `gullet/src/detached.ts` owns both halves) and never a single point of failure: a failed spawn falls through to in-process binding, `DETACH_ATTEMPTS` bounds it, `--no-detach` pins the old shape for debugging. The token crosses on stdin, never argv; hub stderr goes to `$XDG_STATE_HOME/tabglutton/hub.log`, truncated per hub generation. The hub publishes its session count, and the extension arms the keepalive **and its own heartbeat** only above zero (an absent count means entitled). It exits after `DETACHED_HUB_IDLE_EXIT_MS` (6h) idle and retires for a newer peer; `compareGulletVersions` treats an unreadable version as equal, so `GULLET_VERSION` is load-bearing. §Detached hub.
- A protocol bump cannot retire a running detached hub (`shouldRetireFor` runs only after token proof, and moving it earlier would let any local process retire the hub); Gullet's exhaustion fault names the port and `pkill -f "gullet.*--detached-hub"`. **Every `BRIDGE_PROTO` bump needs that step in its release notes.** `docs/BRIDGE.md` §Wire protocol.

## Build, test, and development commands

`package.json` is the reference. The ones that matter: `bun run check` (typecheck + format:check + lint + test — run before committing), `bun run typecheck` (extension via `tsconfig.test.json`, then gullet), `bun test` (`tests/` and `gullet/tests/`), `bun run build` / `build:gullet`, `bun run start` (build Firefox + launch Zen), `start:firefox`, `start:chrome`, `bun run package` / `package:gullet`. CI (`.github/workflows/ci.yml`) runs the same on every push and PR; `prek install` wires the fast format/lint hooks from `.pre-commit-config.yaml`.

## Coding style

TypeScript ES modules with explicit relative `.js` specifiers (`import "./normalize.js"`). Strict typing under `tsconfig.json`: no unused locals or parameters, no implicit `any`, no switch fallthrough. Two-space indent, double quotes, trailing commas in multiline calls, small exported functions. kebab-case filenames, camelCase identifiers. oxfmt formats, oxlint lints.

## Testing

`tests/` holds pure-module unit tests mirroring module names; browser-API surfaces (`background.ts`, `bridge-methods.ts`, `bridge-client.ts`, async `storage` helpers, the content script) are live-only via `bun run start*`. `gullet/tests/` follows the same split, with `hub.test.ts` as the one real-socket exception. Concurrency invariants are unit-tested (`serialize.test.ts`, `mcp.test.ts`). Test files typecheck through `tsconfig.test.json` and are excluded from `dist/`.

**`tsconfig.json` and `tsconfig.test.json` both restate the `include` list** (TypeScript replaces it on `extends`). Add a new directory to **both** — except a directory the build must never emit (`scripts/`), which goes in the test config only. §TypeScript configs.

## Version control

jj in colocated mode: default to plain `git` for everyday work. Reach for `jj` only for what it uniquely does (`jj op log` / `jj undo`, `jj split` / `jj absorb`, `jj describe`); never run `jj bookmark`, `jj rebase`, or other history rewriting without checking with the user first.

## Versioning

- **Patch** for anything the bridge protocol survives, features included; **minor** when `BRIDGE_PROTO` bumps or a new capability class lands. Gullet's version equals the extension's. §Versioning and releases.
- **Write the CHANGELOG section as work merges, under `## [<next>](compare-url) (unreleased)` — never `[Unreleased]`** (the extractor's regex needs a leading digit, and `release:bump` strands content below it). `scripts/release-notes.ts` fails `release.yml` on a version with no section.
- Versions are `major.minor.patch.build`; only the release triple goes in `package.json` / `manifest.json`. The fourth part belongs to `bun run sign:dev` alone — never commit it.
- **The pushed three-part `v*` tag cuts the GitHub release** (`release.yml` verifies it against `package.json`, runs `check`, packages, and publishes with the CHANGELOG section as the body). Tag on `main` after the squash merge; rerun the workflow manually to rebuild an existing tag.

## Commits and pull requests

Commit subjects are concise and imperative; squash-merge titles carry `(#NN)`. Let the subject run as long as the change needs. PRs describe the user-visible change, list verification commands, and mention manifest or permission changes.

**A PR touching markup or CSS under `popup/`, `options/`, `onboarding/`, or `redirect/` carries screenshots** — both themes when the change reaches the tokens — captured with the CDP harness (`scratch-chrome/shoot-store.ts` dark, `shoot-light.ts` light; `docs/STORE.md` §5), never an OS window grab. **Upload them to GitHub's attachment host, never commit them**: `POST https://uploads.github.com/user-attachments/assets?name=…&content_type=…&repository_id=…` with `Authorization: Bearer $(gh auth token)` returns a URL for `gh pr edit --body`. A fresh asset 404s to an anonymous `curl` until a body references it — verify with the token or after the edit. Keep a measured before/after table beside the pictures.

## Security and configuration

Keep `manifest.json` permissions minimal and justify new ones in the PR. Never commit generated profiles, packaged zips, or browser state; WebExtension tooling targets `dist-firefox/` / `dist-chrome/`, never source. `.env` holds **store credentials only** (`WEB_EXT_API_KEY` / `WEB_EXT_API_SECRET` for AMO; `CWS_*` for the Chrome Web Store V2 API, minted by `cws:auth`), all loaded through `scripts/sign-env.ts`; development, building, and `bun run check` work without any of them. `docs/STORE.md` §7.

## Maintaining this file

Keep this file for knowledge useful to almost every future agent session in this project. Do not repeat what the codebase already shows; point to the authoritative file or command instead. A rule stays here as one or two lines; its measured history goes in `docs/ENGINEERING.md` under a section this file cites. Prefer rewriting or pruning existing entries over appending new ones.
